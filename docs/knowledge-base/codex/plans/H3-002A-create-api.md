# H3-002A：创建接口与输入边界

## 目标与事实

从F08固定响应走到实际POST创建、按Location读取，并证明错误请求不会写入。基线83d2aacf292d27b461b17f5dfed94eee6c8416c5，v5与origin同SHA、工作区干净。Node24.21.0/npm11.19.0，既有Quartz/Pages不变。

## 实现范围

两篇：F09A路由/创建/读取/201+Location及内存生命周期；F09B媒体类型→字节上限→UTF-8/JSON→业务校验→写入的边界。新增独立无依赖examples/trip-api，内置HTTP与内存数组；不修改旧教材例子，不把内存保存说成数据库持久化。

1. 实现POST /trips、GET /trips、GET /trips/:id；错误JSON结构稳定，404/405/415/413/400/422分类明确。只监听127.0.0.1随机端口，demo自动关闭。
2. 接收JSON对象，目的地trim后1–80个UTF-16代码单元，天数number整数1–30；仅拣选这两个字段，编号由服务端分配。沿用F06语义，增加明确长度限制；HTTP端点独立验证，不信任前端。
3. 请求正文按实际Buffer字节累计，上限1024，超出后丢弃内容，读完本次正文返回413；不依赖Content-Length，不逐块解析JSON。只接受UTF-8 JSON与identity编码。此教学版不声称抗慢速攻击。
4. 真实本机HTTP测试：201/Location可读、列表、新实例为空、非法类型/范围/JSON/编码、媒体类型、字节边界/分块/超限、失败无写入、重复POST明确产生不同记录。测试具备故意破坏会失败的反例；含空格路径独立运行。
5. 两次正文复核、官方文本来源、必要导航；登记根例子/CI。复用干净安装隔离副本运行适用门禁，记录锁一致。
6. 更新报告、BACKLOG和STATE；按持续授权普通push v5，跟踪同SHA CI/Pages与HTTP文本冒烟。
