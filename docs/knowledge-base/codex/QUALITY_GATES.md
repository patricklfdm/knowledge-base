# 验收规则与证据

## 四类状态不能混用

命令/检查结果：PASS、FAIL、NOT_RUN、NOT_APPLICABLE。任务状态：todo、in_progress、blocked、done。部署状态：not_requested、pending、success、failed、unknown。文章状态见 metadata。用户掌握不记录于公开仓库。

PASS 必须来自实际执行且满足断言；NOT_RUN 必须说明原因和影响。工具不可用不能直接当 PASS。NOT_APPLICABLE 需要范围理由，例如本批只改工程文档且未更动页面，不要求新 UI 截图。

## 自动检查矩阵

| Gate | 内容 | 何时必须 |
| --- | --- | --- |
| G0 identity | 仓库/branch/remote/工作区/提交范围 | 每次接手、提交和发布前 |
| G1 metadata | 类型、唯一 ID、状态一致性、先修存在/无环 | H1 后每次内容批次 |
| G2 links | 正文/图/锚点/别名、构建后 base path | H1 后每次内容/结构变化 |
| G3 publish | draft/unpublished 排除、索引衍生物、附件范围 | H1 起核心过滤；H4 完整；任何发布配置变化 |
| G4 tools | 验证器正常+失败 fixtures，非零退出 | 每次检查器修改，CI 常规 |
| G5 examples | 可复现运行、正常/边界/失败、隔离 | 每个声称可运行的例子 |
| G6 build | 干净依赖环境、插件、Quartz 正式构建 | 每批发布前；依赖变化必做干净环境 |
| G7 UI | 桌面/窄屏、导航/搜索/代码/元数据/键盘 | H2 初验、UI/结构修改及发布冒烟 |
| G8 release | 同 SHA checks 和部署、线上地址/关键页面 | 授权发布后 |

## H1 必需负面用例

缺必填字段；重复 ID；`publish: "false"` 字符串；status=draft 却 publish=true；未知先修、自依赖与依赖环；正文指向不存在文件/锚点；公开正文指向 unpublished 必要先修；代码块中的伪链接不能被误报；导航类兼容；禁发页含合成 marker，不能进入实际发布衍生物。

链接语法与附件矩阵可按支持范围逐步补全，但不支持的语法必须明确报告，不能默默跳过且把完整 gate 标为通过。

H1 的本地阶段可通过负面用例和工作流依赖审查证明门禁结构；不为验证而擅自推送。真实远端运行尚未获得发布授权时标 NOT_RUN，在发布验收补齐，不能把本地证明称为已完成云端验证。

## H2/H3 内容验收

至少一次作者自审与一次独立阅读检查，工具可用时可独立上下文复核，但不要虚构专家背书。每篇关联例子/测试/来源；存在无法解释的核心概念，先修补齐或内容拆分。选择一个读者任务验证，不只检查字数和标题是否存在。

首个应用验收：能创建/查询/修改；非法输入前后端有可理解反馈；参数化数据库访问；数据库约束验证；重启后数据仍在；增加字段有迁移/校验/页面/测试同步；从 README 干净环境能重现。测试用合成数据，无生产写入。

## 门禁不得被绕过

本项目部署与检查存在显式依赖。任何必需检查 FAIL，或者必需验证 NOT_RUN，不能宣称阶段验收/发布准备已完成。对于既有上游格式或平台测试失败，先记录范围，决定是否属于本站必需 gate；不能用全局跳过掩盖本次错误。

判断 CI 失败原因前看第一个实质错误，不只看最后的堆栈。避免在一个问题里同时改依赖、配置、内容和运行时。修复附回归用例。

## 报告最低要求

任务/阶段、基线 SHA、改动摘要、命令与环境、真实结果、证据路径、没跑的项目、内容审阅发现、风险、Git 状态、发布状态、下一项任务。使用 templates/ACCEPTANCE_REPORT.md。

报告描述工作区时可以用父提交 SHA+diff 摘要，不需要为了把“本提交 SHA”写进自身文件反复 amend。推送后记录实际部署 SHA，维护一份报告即可。

## 回滚

发布回退优先普通 revert 并重新走同门禁，不重写远程历史。回滚目标须经过用户本批授权范围核对；先证明回退解决问题且没有覆盖其他工作。工作区恢复只能处理自身生成的临时文件，不能删除用户内容。

## H3 内容优先阶段例外（用户于 2026-09-11 明确批准）

按 OPERATING_MODEL 的当前覆盖执行：G7 从当前内容批次移至 H4-UI-SITE；教学应用真实提交、键盘焦点与辅助技术反馈移至 H4-UI-APP。结果统一为 NOT_RUN，原因“用户批准移至集中验收阶段”。既有失败不得改写。恢复浏览器需用户明确允许，不能在每篇完成后自行恢复。

内容 done/reviewed 依据来源、作者自审、另一次读者任务复核、例子与非浏览器门禁；报告和文章核验段明确 UI 未测。H3-GATE 验收内容和非浏览器业务闭环；H4-GATE 仍需集中 UI 验收。当前用户的持续自动 push 授权同时覆盖内容批次的这项延期，不降低现有 CI，不把发布 success 写成 G7 PASS。G8 使用同 SHA CI/部署及 HTTP 文本冒烟。

无依赖变化时可复用本会话已干净安装的隔离验证环境，受控同步当前源码并记录锁摘要；依赖变化必须重新干净安装。每批做必要正式构建，不为每次保存反复安装。
