# 验收报告：填写任务 ID

## 范围与基线

日期/时区；任务；基线 SHA；工作区已有改动处理；本次修改的路径与用户可见收益。

## 验证

| Gate / 命令 | 环境 | 结果 | 证据 | 备注 |
| --- | --- | --- | --- | --- |
| 待填写 | 实际版本 | NOT_RUN | 无 | 未执行前不得改 PASS |

区分 FAIL、NOT_RUN、NOT_APPLICABLE。证据可以是报告内节、受维护测试文件、脱敏日志或 CI run。不能只写“所有测试通过”。

## 内容与阅读检查

哪些学习目标得到验证？来源是否核对？示例是否与正文一致？桌面/窄屏检查怎样执行？没有相关改动则说明不适用。

## 问题与风险

区分已有 baseline failure 和本次回归。列不能确定的行为、影响及下一步。

## Git 与发布

本地提交/尚未提交；是否获得本批次发布授权；部署 not_requested/pending/success/failed/unknown；实际推送 SHA 与 workflow；线上冒烟；回滚方案。

## 结论与恢复点

哪些任务可标 done、哪些不能；下一任务 ID、计划路径、下一条动作。更新 BACKLOG/STATE 的具体内容。
