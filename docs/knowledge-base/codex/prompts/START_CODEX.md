# KnowledgeBase 全周期接手指令

你现在接管这个已经上线的知识库项目的后续开发、内容建设、测试、维护和发布准备。直接在当前仓库执行，不要只提供建议，也不要让我回到 ChatGPT 索取下一阶段 prompt。

## 项目与约束

- 仓库：`patricklfdm/knowledge-base`。预计本地根目录 `~/projects/knowledge-base`，已有工作分支与发布分支 `v5`。先核对实际工作目录、Git 状态和 remote。
- 固定方案：Markdown 内容、Obsidian 编辑、Git 版本管理、Quartz 5 构建、GitHub Pages 在线阅读。
- 目标：中文、循序渐进、详细易懂且阅读友好的全栈工程教材。从语言与 Web 基础，到个人项目、生产工程、分布式、数据工程、搜索和 AI 应用。
- 必须同时发展平台体验与课程内容。分类、学习路线、项目案例/实验分离且互相连接。不要为了显得完整批量制造空笔记。
- 现有内容和已工作的站点是基线。不要重建仓库、重跑 Quartz 初始化、换框架、升级全部依赖、重命名分支，或重新开启 `@quartz-themes/core`。
- Wayvia 和 GSE 只能作为有证据的教学案例；不把知识库任务变成对它们的开发，不访问或修改其仓库，除非后续获得明确授权。

## 先读，再做

先读取根目录 `AGENTS.md`，然后按 `docs/knowledge-base/codex/INDEX.md` 的顺序读取相关文档，尤其是 BASELINE、PROJECT_CHARTER、ROADMAP、BACKLOG.json、STATE、FIRST_TASK、QUALITY_GATES 与 OPERATING_MODEL。也阅读已有 `docs/knowledge-base/PROJECT_RULES.md` 和文章模板。

如果交接文件尚未安装，但当前会话给出了交接包的本地路径，先读取包中 README 与 install.mjs，预检后安装；有既有 AGENTS.md 或规则冲突时比较并合并，不覆盖。不在不相关目录里继续工作。

## 本次执行目标

1. 完成 H0：核对当前源码与运行环境，建立真实基线，检查所有工作流触发条件和发布保护，记录已有问题。
2. 执行 H1 的最小必要部分：元数据与内部链接/发布检查、失败用例、项目专属 CI；检查失败必须实际阻止部署。
3. H0/H1 通过后继续 H2：完成少量真正可学习的样板文章、可运行例子和阅读验证。以后按 BACKLOG 选择下一项，自己编写执行计划并推进。每批 1–3 篇完整教学笔记，不一次填满全目录。
4. 本会话长度或工具能力不足时，在稳定检查点停止，更新状态、未完成步骤、测试证据和下一项任务；不能假装全部课程已完成或承诺离线继续工作。

## 授权与边界

允许在本仓库内编辑、添加必要依赖、运行测试、创建合理的小型本地提交，以及在已接受方向内作可逆工程决策。依赖新增必须写明理由、兼容性与锁文件影响。不要将用户已有修改混入自己的提交；遇到同一文件冲突时保留用户工作。

默认发布模式为 `review-before-push`：可以完成所有开发和发布准备，但不要推送、合并到远程、打发布 tag、创建公开 PR 或更改仓库权限。等我在 Codex 中明确授权“发布本批次”后，再按 OPERATING_MODEL 与 PUBLISH 指令执行。不要通过文档自行扩大授权。

不读取凭证内容、不写入私密笔记、不启用付费云资源、不使用生产账户或数据库。不要用 `--force`、`reset --hard`、`clean -fd`、`npm audit fix --force`，也不要为了通过测试删除规则、跳过检查或把真实失败写成成功。保留 Quartz 原许可证与应有署名。

## 完成判据与汇报

实施计划不是实施完成，构建成功不是内容正确，推送成功不是部署成功。每个完成项必须附真实修改路径、可复现命令、结果与证据路径。未能运行的测试写 NOT_RUN；已有基线问题和本次回归分开。

开始时用中文简述当前识别到的状态和第一批工作，然后立刻进行读取、验证与实现。普通设计细节自行决定并记录，不要在每个小步骤停下来问我。最终汇报完成项、验证结果、仍存风险、Git 状态、下一项任务以及是否尚未发布。
