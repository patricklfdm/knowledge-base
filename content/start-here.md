## 这套知识库怎样使用

第一次接触一个领域时，先选择学习路线。带着具体开发问题来时，从知识地图或搜索进入。读完关键概念后，完成相应练习或实验，再尝试把它应用到项目中。

[进入全栈基础路线](roadmaps/fullstack-foundations.md) · [打开知识地图](knowledge-map.md)

## 三种组织方式不混为一谈

**学习路线**规定学习顺序、先修知识与过关条件。

**知识地图**为概念提供稳定位置。同一篇文章可以被多条路线引用，不复制多个版本。

**项目与实验**记录问题的真实约束、采取的方案，以及验证的范围。

## 难度不等于熟练程度

| 层级 | 学习目标 |
| --- | --- |
| L0 | 能写、运行和调试小程序 |
| L1 | 能完成页面、接口、数据库组成的端到端功能 |
| L2 | 能维护项目、编写测试、管理契约与部署 |
| L3 | 能处理性能、安全、监控、恢复和发布问题 |
| L4 | 能解释跨节点协作的故障与一致性边界 |
| L5 | 能建立可验证、可重放的数据处理流程 |

这是一套导航约定，不代表所有学习者必须按一条直线走完。已有基础的人可以通过自测跳过内容。

## 阅读后的三个问题

不看正文，是否能解释这个概念？改变一个条件后，是否还能完成任务？是否知道这个方法何时失效？

文章状态表示内容的编辑进度；个人掌握状态需要单独记录。个人记录不放在当前公开内容目录。

## 发现错误时

保留文章路径、具体段落、适用版本与复现步骤。没有实际运行的代码只能标为未验证示例，不能写成已通过测试。
